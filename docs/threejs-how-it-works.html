How Three.js works

This page’s pieces ↔ the temple game. Paths under client/src/ unless noted.

  1. Boot — this whole page ≈ main.ts → game.ts startGame().
  2. Scene / camera / renderer — game.ts (THREE.Scene, PerspectiveCamera, WebGLRenderer).
  3. Lights — day/sun in world/sky.ts (buildSky); hall lamps in world/lightPool.ts (LightPool).
  4. Floor / platform / plinth — hall shell + altar in buildings/hall.ts (buildHall); plinth boxes in buildings/statue.ts (buildStatueSlot).
  5. Statue GLB — buildings/statue.ts + content/manifest.ts (loadModelMap) ← public/assets/models/index.json.
  6. Simple avatar (this page) → full monk player/avatar.ts (Avatar), owned by player/localPlayer.ts / remotes in net/remotePlayers.ts.
  7. Walk + turn — input core/input.ts; movement player/localPlayer.ts; camera follow player/cameraRig.ts (game is not this third-person drag).
  8. Frame loop — game.ts renderer.setAnimationLoop → update systems → renderer.render(scene, camera).
  9. Hall layout data — which deities/sizes: config/layout.ts (HALLS); deity heights: config/deities.ts.

Serve the repo root: npx --yes serve . then open /docs/threejs-how-it-works.html (needed for the .glb).
